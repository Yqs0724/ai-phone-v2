# AI 小手机 v2 · 需求文档（SOP 七段式）

> 格式对齐目标公司官方需求 SOP：问题描述 → 原始需求 → 场景描述 → 竞品分析 → 可能方案 → CheckList → 功能清单
> 本文档同时是 JD1「需求擅长」岗的投递材料——每个【待补充】都是留给你把个人体验换成证据的位置

## 1. 问题描述

AI 陪伴/角色扮演品类存在品类级的「剧情同质化」问题：人设开篇剧情耗尽后，对话在约数十轮内退化为无冲突的恋爱日常，且不同人设后期趋同（模型向"安全甜"语气收敛）。同质化有明确生命周期：

```
开篇兴奋期 → 设定耗尽 → 平淡期（复读/原地踏步） → 用户自救（改人设补丁/社区抄梗） → 弃坑开新崽
```

v1 已解决"失忆"与"主动性"，但同质化仍无解——编剧劳动全在用户身上。

## 2. 原始需求（来源 + 未加工资料）

来源：本人（深度用户）真实使用原话，未加工：

> "必须要自己一直想话题。最初设定的人设开篇走完剧情后，就进入了无聊的恋爱期（不管最初人设如何，后期都变得同质化）"

> "手动改人设/加新设定强行续命；去社区抄作业找灵感，收藏剧情点子、角色卡、Prompt 技巧；聊不动了就弃坑开新崽"

【待补充：星野/bubbly 社区同类吐槽截图 2-3 张（"个人感受 → 普遍规律"的佐证）】

## 3. 场景描述 / 用户行为路径

**典型场景**：周五晚上，用户与角色聊天进入平淡期。

当前路径（痛苦版）：
```
打开聊天 → 没话题硬想（5-10 分钟）→ AI 回应平淡 → 去社区翻灵感（15+ 分钟，散落各处）
→ 找到梗但和人设对不上 → 手动改编 → 勉强续命 or 弃坑
```

期望路径（v2 版）：
```
打开「给梗」→ 系统按当前人设从弹药库匹配素材 → 3 个带开场白的桥段（10 秒）
→ 挑一个粘贴继续聊
```

## 4. 竞品分析

详见《对比体验报告-甜气vs星野vsbubbly》（另附范文对照版）。要点：

- 三款主流产品均无内置剧情供给机制【待甜气实测回填最终结论】
- 星野社区有大量剧情攻略，但与聊天场景不连通——灵感存在，"最后一公里"断裂
- 结论：品类空白 = 「收藏 → 结构化 → 按人设供给」的打通

## 5. 可能方案

| 方案 | 思路 | 取舍 |
|---|---|---|
| A. 纯给梗工具 | 粘贴人设直接生成桥段，无素材库 | 快但无沉淀，梗无个人偏好来源 |
| B. 纯素材库 | 收藏打标可检索，不管生成 | 解决了"乱"，没解决"救场那 10 秒" |
| **C. 弹药库（采纳）** | 素材入库（LLM 打标）→ 按人设匹配 → LLM 改写成 TA 风格桥段 | 梗从自己的收藏长出来，差异化有来源；且记忆系统可给梗去重 |

技术约束：复用 v2 统一 LLM 层 + SQLite；反同质化约束写入给梗 Prompt；A/B 对比（有无约束）作为效果验证。

## 6. CheckList

- [ ] 体验优化：给梗输出≤10 秒；桥段附"人设契合说明"（建立信任）；支持一键复制开场白
- [ ] 收入设计：【个人项目不涉付费，投递时改写为"若产品化：供给型订阅（编剧模式）"】
- [ ] 自动化落地：素材打标全自动（入库即打标）；给梗匹配自动化；标签词表初期人工约束防漂移
